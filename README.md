# عبود Trading Controller — v22
## اتصال WebSocket وإدارة الحسابات

نسخة مبنية على ملف v21 المرفق. الحساب المالي المؤكد بالصفقة وصور البراند ومزامنة MetaTrading وحدود المال والعائد والوقت والتعزيز محفوظة. التغييرات تخص الاتصال وإدارة الحسابات وواجهاتها مع اختبارات انحدار.

## النشر والاستخدام الأول

1. أوقف التداول وانتظر حسم الصفقة المفتوحة قبل النشر، ولا تمسح قاعدة MongoDB.
2. استبدل المشروع كاملاً بمجلد `po_autotrader`، بما فيه `assets/brand` والملف الجديد `connection_lifecycle.py`.
3. احتفظ بمتغيرات Render الحالية. لا متغيرات جديدة مطلوبة. Build: `pip install -r requirements.txt`، Start: `python -u run.py`، Health: `/health`، Readiness: `/ready`.
4. تحقق من `[APP] build=v22-connection-account-manager` ثم افتح `/start`.
5. إدارة الحسابات → قائمة الحسابات → بطاقة الحساب المطلوب → اختيار الحساب إن لم يكن نشطاً → **اختبار / إعادة اتصال**.
6. إذا انتهت الجلسة، استخدم **تجديد الجلسة SSID**. تعديل رابط WebSocket وحده لا يجدّد توكن مصادقة منتهي الصلاحية.
7. انتظر تأكيد المصادقة ووصول الرصيد، ثم ابدأ على PRACTICE. لا يبدأ التداول تلقائياً عند الاختبار أو التعديل أو اختيار الحساب.

نصلح عيوباً مثبتة في الكود، لكن لا توجد جلسة حية أو سجلات اتصال من حساب المستخدم ضمن هذا الملف. لا ندّعي إثبات سبب الانقطاع في استضافته أو ضمان تجاوز رفض المنصة أو انقطاع شبكتها.

## ما أصلح في الاتصال

### دورة الحساب النشط

كان v21 يسمح بإضافة UID موجود كتحديث صامت لجلسته، وقد يغلق اتصال الحساب النشط. ثم اختيار نفس الحساب يرجع «نشط بالفعل» دون محاولة إعادة الاتصال. الآن الإضافة والتعديل منفصلان، والاختيار يعيد الاتصال إذا كان الحساب النشط غير متصل، وزر مستقل يختبره دون تداول.

مقارنة بيانات الاتصال صارت مقارنة auth والرابط الفعليين بعد التطبيع، لا مساواة قاموسين حرفياً. في الترحيل قد يحتفظ الحقل الجانبي uid=0 بينما إطار auth يحتوي UID صحيحاً وسجل الحساب يحتفظ به كرقم؛ لا يعني ذلك اختلاف الحساب أو أن الاتصال غير موجود. اختلاف توكن الجلسة الفعلي أو النوع أو الرابط يظل اختلافاً حقيقياً.

### النقل والبروتوكول

`connection_lifecycle.py` يفصل إنشاء الاتصال عن إرسال الصفقات:

- TLS والتحقق من الشهادة مستمران؛ لم يُعطّل التحقق الأمني.
- بناء اتصال جديد دون إعادة استخدام معامل Engine.IO `sid` الذي يخص اتصال متصفح سابق. لا يحذف توكن auth أو حقول المصادقة الأخرى.
- دعم ترويسات `additional_headers`/`extra_headers` حسب نسخة مكتبة websockets، وتعطيل proxy التلقائي في واجهة المكتبة التي تدعمه.
- المهلة والمصادقة والرصيد منفصلة في التشخيص. لا يُظهر اختبار الاتصال رسالة نجاح مالي قبل معرفة الرصيد.
- Engine.IO 4 يرد على ping المنصة ويحافظ على حمولة pong، ويراقب انقطاع النبضات. Engine.IO 3 يرسل client ping وفق pingInterval المعلن وينتظر pong. لا يبدل EIO عشوائياً أو يغير مضيف الحساب تلقائياً.
- معالجة أغلفة auth الثنائية وJSON وحزم متعددة مفصولة بمحدد Engine.IO.
- ثلاث محاولات محدودة للاتصال العابر فقط؛ رفض المصادقة أو اختلاف UID/نوع الحساب يحتاج بيانات صحيحة ولا يُتجاوز بإخفاء الخطأ.
- لم نعد نفترض أن `user.id` العام داخل ملف profile هو UID مصادقة مختلف: حقل UID الصريح هو أساس التحقق، وتظل المخالفة الصريحة أو نوع الحساب الخطأ ممنوعة.
- عند انقطاع الاتصال أثناء انتظار الإشارة تُلغى الإشارة القديمة ويعاد الاتصال بين الصفقات. عدم توفر الشبكة قد يبقيه في إعادة اتصال حتى Stop.
- إذا فشل حارس الاتصال قبل إرسال openOrder فعلياً، يُسجَّل كأمر لم يرسل، لا كصفقة مجهولة أو خسارة. إذا بدأ الإرسال ثم انقطع، تبقى سياسة v21 الآمنة: لا إعادة إرسال أو تخمين نتيجة.

السجل يعرض رموزاً مثل PO_AUTH_REJECTED أو PO_UID_MISMATCH أو PO_CONNECT_TIMEOUT أو PO_PROTOCOL_FAILED أو PO_HEARTBEAT_TIMEOUT ومرحلة open/namespace/auth/receive. لا تطبع طبقة التشخيص إطار auth أو SSID أو رابط الحساب أو نص سبب الإغلاق الخام.

يمكن أن تستمر «غير متصل» بسبب جلسة منتهية أو مضيف يرفض اتصال الاستضافة أو اختلاف حساب حقيقي/تجريبي. زر الاختبار يعطي كوداً ومرحلة محددين لتحديد الإجراء بدل إظهار حالة وهمية «متصل». عند استمرار المشكلة أرسل الكود والمرحلة فقط؛ لا تشارك الجلسة أو رابط MongoDB أو رابطاً يتضمن أسراراً.

## إدارة الحسابات — بطاقة لكل UID

الرئيسية → إدارة الحسابات → قائمة الحسابات → بطاقة UID.

البطاقة تعرض UID والنوع والاسم الاختياري، النشط/غير النشط، حالة WebSocket للحساب النشط، صافي السجل وكود الاتصال الأخير إن توفر. الحساب غير النشط يعرض أنه غير مختبر؛ لا ينسب إليه اتصال حساب آخر. الجلسة والرابط لا يظهران في البطاقة.

الأزرار:

- **اختيار هذا الحساب**: مع تأكيد، وتحذير REAL، ثم اتصال دون بدء التداول.
- **اختبار / إعادة اتصال** للحساب النشط: مصادقة ووصول رصيد، لا إرسال أوامر. أوقف التداول أولاً؛ لا يقطع صفقة معلقة.
- **تجديد الجلسة SSID**: إطار auth جديد أو SSID خام لنفس UID؛ في التجديد يمكن استخدام UID الحساب المحفوظ للرمز الخام. ثم رابط جديد أو `/skip` للاحتفاظ بالرابط الحالي، واسم أو `/skip` للاحتفاظ بالاسم. UID مختلف لا يستبدل الحساب، بل يُضاف كهوية جديدة.
- **تعديل رابط WebSocket**: يغير الرابط فقط دون تغيير UID أو الجلسة أو الإحصائيات. يحفظ بعد التحقق من نطاق المنصة وEIO وtransport. إن كان الحساب نشطاً تُبطل الوصلة القديمة، ثم اختبر الاتصال من البطاقة.
- **تعديل الاسم**: اسم مختصر أو `/clear` لحذف الاسم فقط. لا يقطع الاتصال.
- **حذف الحساب**: شاشة تأكيد صريحة وإلغاء. تزال بيانات اتصاله والجلسة من الحسابات المتاحة والحقول المختارة، دون اختيار حساب بديل أو بدء REAL تلقائياً.

أي إضافة لنفس UID ونفس REAL/PRACTICE تُظهر «هذا الحساب موجود من قبل» قبل استبدال أي بيانات، مع أزرار بطاقته للتعديل. وجود UID نفسه في REAL وPRACTICE يمثل سجلين منفصلين وليس تكراراً خاطئاً. يتأكد التخزين أيضاً من عدم التكرار، حتى مع ضغطات إضافة متزامنة.

إضافة حساب جديد: اختر النوع، أرسل auth الكامل أو SSID مع UID الصحيح، ثم الرابط والاسم الاختياري. الإضافة لا تبدل الحساب النشط. السعة حتى 50 حساباً وقائمة مقسمة إلى صفحات عند الحاجة. `/cancel` يلغي الإدخال. عند تجديد الجلسة أو الرابط للحساب النشط يجب إيقاف التداول أولاً. وجود صفقة معلقة يمنع التعديل والحذف والتبديل إلى أن تُحسم.

## ماذا يعني حذف الحساب

الحذف يزيل بيانات SSID والرابط من السجلات النشطة ومرايا النوع المحدد، فلا يعيده ترحيل MongoDB عند الإقلاع التالي. إذا كان نشطاً يتوقف التداول ويصبح الاختيار فارغاً؛ اختر حساباً آخر بنفسك. لا تتأثر جلسة حساب نشط آخر عند حذف حساب غير نشط.

يبقى أرشيف علني للـUID والاسم والنتائج وحالة الحساب دون credentials. لا يغير الحذف الصافي التاريخي الإجمالي ولا يمحو صفقات سابقة. إذا أعدت إضافة UID نفسه يمكن استعادة تاريخه دون استعادة توكنه المحذوف. التصفير المالي المؤكد يصفر السجلات المحفوظة والمؤرشفة، لكنه لا يعيد بيانات اتصال محذوفة. هذا حذف من بيانات التطبيق الحالية، وليس وعداً بمسح نسخ MongoDB الاحتياطية الخارجية.

## الحسابات المالية وميزات v21 المحفوظة

المسار الحي يستخدم CloudPocket وDealTracker: ربط requestId بمعرّف الوسيط ثم نتيجة إغلاق مطابقة. فرق الرصيد أو Accuracy أو العائد المتوقع ليس نتيجة صفقة. النتيجة تحفظ مرة واحدة مع التدبيل والتعزيز والإحصائيات، وتحديث الواجهة لا يحسم أو يكرر الصفقة.

profit/netProfit في المخطط المدعوم صافي مالي، والمرتجع الإجمالي الصريح تخصم منه قيمة الدخول. تعارض البيانات أو غياب معرّف موثوق أو صفر profit مبهم لا يتحول إلى خسارة افتراضية. النتيجة المتأخرة يمكن حفظها لنفس الأمر دون إعادة إرساله. عند عدم تأكد الإغلاق يتوقف الدخول الجديد ويحفظ الأمر للتحقق؛ لا تنمو خسارة التعزيز بالتخمين. راجع زر «تحقق من الصفقة المعلقة» في الحالة.

حماية عائد الزوج وحدود المال (مثل 200$ ربح) والتشغيل/الراحة (مثل 10 دقائق/10 دقائق) والتعزيز ومزامنة MetaTrading وصور البراند بقيت كما سبق. الحدود المالية توقف الدخول التالي ولا تلغي صفقة قُبلت بالفعل. إكمال السلسلة عند نهاية الوقت لا يتجاوز Stop أو حدود المال أو حظر العائد. الاستراحة لا تضمن تحسن الإشارات، والمضاعفات تزيد الخطر.

حُذف «العوائد المستلمة» من العرض كما في v21، والتقرير يفرق بين عائد الزوج النسبي وصافي الربح النقدي. التاريخ القديم لم يعدّل بالتخمين. إحصائيات UID/النوع مستقلة، لكن مبالغ التداول وسياسة الحدود والعائد والجدولة عامة، فراجعها قبل تشغيل حساب آخر.

## الاختبارات وحدود التحقق

شغّل `python -m unittest discover -s tests -v` من مجلد المشروع. `verification.json` يسجل عدد الاختبارات ونجاحها وبصمات الملفات المحفوظة.

اختبارات v22 تحاكي تسلسل WebSocket فعلياً: greeting → namespace → auth → رصيد → ping/pong → قطع/إغلاق، مع جلسات وهمية فقط، إضافة إلى حسابات متعددة والتكرار والتعديل والحذف وعدم عودة الحساب المحذوف بعد إعادة التهيئة، وفشل الحفظ، والمصادقة المرفوضة، واختلاف UID، وتوافق نسخ مكتبة websockets. اختبارات v16–v21 المالية والمزامنة والجدولة ما زالت تعمل.

لم يُختبر هذا الإصدار بجلسة المستخدم الحية ولم تفتح صفقة حقيقية أثناء التطوير. نجاح المحاكاة ليس ضماناً لعمل كل مضيف أو مخطط جديد أو لعدم انقطاع الشبكة أو للربح. ابدأ على PRACTICE، ولا تعطل تحقق الهوية أو حماية النتائج لإجبار الدخول.
